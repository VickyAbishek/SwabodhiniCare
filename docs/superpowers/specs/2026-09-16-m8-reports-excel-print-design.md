# M8 — Reports, Excel and Print — Design

> Written 2026-09-16, on `feat/m8-reports-excel-print`, branched from `main` after PR #10 merged.
> Implements main spec §7 and POC spec §10. Scope tags follow `docs/architecture/scope-map.md`.

**Goal:** Give management the six remaining reports (R2–R7) with filters and a Download-Excel button, an A4 printable Individual Assessment Report, and the in-browser Excel builder that every report (and M9's backups) will reuse. R1 (My Queue) already shipped in M6 as the home screen, so it is out of scope here.

## What already exists

- `reports.get` is declared in `shared/actions.js` and gated on the `reports.view` capability (`shared/permissions.js`: THERAPY_HEAD, CENTRE_HEAD, DIRECTOR, ADMIN).
- The `Applications` tab stores **every form answer as its own column** (one column per `field.id`, generated by `Store.gs`), plus denormalized summary columns `centre`, `status`, `applicant_name`, `dob`, `gender`, `suitability`, `programs`, `created_by`, `submitted_at`, `decided_at`. Report fields such as `s3_income`, `s4_conditions`, `s2_udid_status` are therefore directly readable — no JSON parsing.
- `Approvals` holds the review trail (`stage`, `action`, `comment`, `user_id`, `form_hash`, `created_at`); `Users` holds staff names; `Centres` holds centre names.

## Design decisions

**D1 — The maths runs server-side.** `Reports.gs` reads rows and calls `shared/reports.js` to compute summaries; the browser only renders and builds Excel. This matches scope-map F16 ("screens + maths in `shared/reports.js`; rows read from the Sheet"), keeps the browser thin, and leaves `shared/reports.js` as the single source of truth for the bucket definitions (age bands, turnaround thresholds) that Phase 1's SQL must reproduce.

**D2 — One reports screen.** A single `reports.html` hosts R3–R7 behind a report picker (the main spec §14 code layout shows one file). R2 is `print.html`. R1 is the home screen (done).

**D3 — Per-report access follows the spec's "For" column**, layered on top of the `reports.view` gate, plus centre-scoping for Heads. The single broad `reports.view` capability stays as the "may open reports at all" check; a per-report role table decides which report names a role may request, and the server enforces it.

## Access matrix (main spec §7 "For")

| Report | Roles |
|---|---|
| R2 print | THERAPY_HEAD, CENTRE_HEAD, DIRECTOR |
| R3 register | THERAPY_HEAD, CENTRE_HEAD, DIRECTOR, ADMIN |
| R4 monthly | DIRECTOR, ADMIN |
| R5 turnaround | DIRECTOR |
| R6 waitlist | DIRECTOR, CENTRE_HEAD |
| R7 demographics | DIRECTOR, ADMIN |

Centre-scoping: a CENTRE_HEAD sees only their own centre's rows — the same rule `Applications.list` already applies (and a THERAPY_HEAD sees their centre's rows the same way). The centre filter a scoped role sees is fixed to their centre; only Director/Admin may pick "all centres".

## Reports

Common shape: every report answers one management question, supports the filters below (as applicable), renders as a table and/or CSS bar chart, and has a **Download Excel** button that hands the *same* rows to `xlsx.js`.

- **Filters** (from main spec §7): centre, date range, status, program, age band. Charts are plain CSS bars — no chart library.

**R3 Application Register** — *"every application"*. Table: app no, registration no, name, age (from dob), gender, centre, status, therapist (created_by → name), submitted date, suitability. Filters: centre, date range, status, program.

**R4 Monthly Summary by Centre** — *"numbers per centre per month"*. For each centre × month: submitted → admitted / waitlisted / rejected. Grouped CSS bar chart. Filters: date range (month), centre.

**R5 Pending & Turnaround** — *"where applications are stuck"*. Current status, days in the current stage, average days per stage overall, and rows older than 7 days highlighted. **Carry-forward:** a rejection's date comes from its `Approvals` row, not `decided_at`, which no rejection writes (M6 plan, carry-forward 2). Filters: centre, status. Director only.

**R6 Waitlist** — *"waitlisted applicants"*. Waitlisted applicants by centre, program and waitlist date. Filters: centre, program.

**R7 Demographics** — *"age bands, gender, co-conditions, UDID status, income bands"* (CSR / donor / grant use). Age bands and income bands come from the schema's own option lists; co-conditions from the `s4_conditions` multi. CSS bar charts. Filters: centre, date range, program, age band.

**R2 Individual Assessment Report** — the A4 print (below), reached from the register, review and decision screens.

## Excel builder (`public/js/xlsx.js`, `[SHARED]`)

~150 lines, no library, per main spec §11.1: SpreadsheetML wrapped in a ZIP (deflate) with a correct CRC32, UTF-8 so Tamil survives. Public API: `buildXlsx(sheets) -> Blob` where each sheet is `{ name, headers, rows }`; a helper `downloadXlsx(filename, sheets)` triggers the save. English headers on the register/demographics sheets; cell values exactly as entered. Same builder is reused later by M9's backup-Excel.

## Print report (`print.html` + `public/css/print.css`, `[SHARED]`)

R2 renders one application for **Print → Save as PDF** on A4 (no PDF library). Contents: header (app no, registration no, centre, date), all 11 form sections with the chosen language's labels, suitability, the review trail in order (stage → action → actor → comment → time), and the Director's signature image + name + time. Bilingual section headings; the printed report is always light (dark text on white) regardless of theme. Reached from register/review/decision with the application id; gated on the R2 role set.

## Data flow

1. Browser loads `reports.html`, picks a report and sets filters.
2. `api.js` → `reports.get` with `{ name, filters }`.
3. `Reports.gs` verifies `reports.view` + the per-report role table + centre scope, reads the needed rows (`Applications`, `Approvals`, `Users`), applies filters, calls `shared/reports.js` to compute the summary, and returns it (paged at 50 where a report is row-shaped).
4. Browser renders the table/bars; **Download Excel** calls `xlsx.js` on the already-rendered rows.

## Testing

- **Unit** (`node:test`): `shared/reports.js` — every summary function against fixed row fixtures, age-band and turnaround boundaries, the R5 rejection-date rule. `xlsx.js` — CRC32 correctness, Tamil bytes round-trip, output that opens in a reader.
- **Integration** (`tests/poc/reports.test.js`, fake services): `Reports.gs` — role scoping, the per-report matrix, centre scoping, filter application, paging.
- **Browser**: each report renders; a real `.xlsx` download opens; the print page shows the signature + registration number and prints A4.
